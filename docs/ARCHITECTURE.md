# Architecture

`server.mjs` is the loopback HTTP adapter. The browser renderer starts in `public/app.js`. Fab remains a separate file-backed source. The browser components use the following boundaries.

- `public/catalog/` owns folder sessions, saved categories, and the pack and file list views.
- `public/library/` owns the indexed library interface, quality profiles and cached thumbnails. The importer is in `public/package-importer/`.
- `public/preview/loaders/` loads models, decodes images and resolves preview resources. `public/preview/materials/` binds textures and normalizes preview materials. `public/preview/scene/` handles scene parts, root motion and resource disposal. The stage coordinates these components and renders the result.
- `core/library/local-folders.mjs` groups assets discovered in a user-selected folder. `core/materials/unity/` resolves Unity material, prefab and texture metadata for that library. The backend and browser share the pure collision naming rules in `public/shared/`.

`core/files/` owns scoped file access, discovery and the shared format registry. `core/index/` owns SQLite, migrations, assets, version history, full-text search and review fields. `core/analysis/` contains technical analysis and quality profiles. `core/processing/` owns the durable queue, worker lifecycle and library watching. `core/thumbnails/` contains the PNG renderer and its cache. `core/http/` adapts the core APIs for the browser. Indexed search results open in the existing renderer.

Asset roots are user-selected, canonical directories. Discovery skips child symlinks and junctions. File paths stay relative to their root until opened. Application paths are resolved by `core/config/data-paths.mjs`.

The SQLite job queue records scan progress and permits one active scan job per library. The HTTP process claims jobs using a renewable lease. The successful result and updated assets commit in the same transaction. Pending jobs resume after startup. An expired running job is marked interrupted and can be retried.

Schema 13 persists pause requests for package imports. Once a paused worker has released its lease, SQLite keeps the existing source fingerprint, export recipe and queue slot. Other queued jobs can still run. The worker discards temporary data before releasing the lease, and an expired lease preserves the paused state. Resuming the same job starts from source verification and can use verified completed cache entries. A paused run does not count toward the failure retry limit.

`LibraryWatcher` registers native recursive notifications for roots with an explicit SQLite opt-in. It groups nearby events into incremental scan jobs and retains changes received during a running scan for a follow-up. It reconciles at startup, when an unavailable root returns, and every 15 minutes. Reconciliation also covers filesystems without usable native notifications. Automatic jobs run at a lower queue priority than manual jobs and share the same discovery and path checks.

Schema 11 stores package-watching preferences per library and format. Migration preserves the `.unitypackage` opt-in and job history. `core/packages/watch-formats.mjs` declares candidate extensions and export formats. `core/processing/package-watch.mjs` reads hashes from the committed scan and records the source version, expected format and job ID in the same transaction that queues each import. The worker verifies the archive content and staged copy before decoding. A scan completion, an import completion or failure, or a watcher refresh can fill available queue slots. Automatic imports share the engine-free recipes, report publication and output library scans with manual jobs. One queue slot remains available for manual import.

Schema 12 adds the `unity-serialized` opt-in. `core/packages/unity/bundle/watch-source.mjs` verifies the binary header and fingerprints matching companions during library scans. Companion hashes are reused when the file identity, size and timestamps match. The scan commits the combined key with the asset record. A sidecar change schedules a scan when a library is watched, and the worker verifies the key again against all staged bytes before publishing.

The scan reads bounded glTF/GLB/VRM and Wavefront OBJ/MTL data and supported image headers outside the SQLite transaction. It reuses existing analysis when the processor version, path and content still match. Technical metrics and explicit dependency rows commit with the asset updates and scan result. Dependencies resolve within the same library's committed index. OBJ texture links resolve one step through indexed material libraries, so changing a texture or MTL updates the next report without rewriting the OBJ.

Quality validation uses the current index report and the selected profile on demand. Profile edits use optimistic revisions and store their overrides in the same SQLite database, including backups. Evaluation is shared across interfaces and requires no extra scan.

Thumbnail generation uses the SQLite jobs table and a dedicated worker slot, so scans and previews can run concurrently. A lease and a unique index cap rendering at one running thumbnail job per database across the HTTP server and CLI. Pending work survives restarts. The renderer uses the pinned Three.js geometry loaders and a bounded software rasterizer in a terminable Node worker. The source and indexed geometry buffers must match their recorded file fingerprints and SHA-256 hashes. Publication checks the lease and source version and atomically renames the PNG from a staging file.

Generated 160 × 160 PNGs live in an application-owned directory shared by the HTTP server and CLI. The key includes content hashes, relative geometry buffer references, processor version, format and resolution. Thumbnail retrieval verifies current indexed inputs before serving output. A 64 MiB default quota evicts the least recently used files, and entries expire after 30 days without an HTTP image read. The cache is disposable and separate from database backups.

`core/packages/archive/` handles bounded archive reads. `core/packages/unity/` separates package limits, path validation, inspection, report generation and staged publication. The Unity importer uses the same SQLite queue as scans and thumbnails. One import can run per database at a time, with at most 16 active or queued imports. The browser UI lives in `public/package-importer/`.

`core/packages/folder.mjs` performs bounded discovery for one-time folder imports. It probes file signatures, excludes managed output directories and returns relative paths for review. `public/package-importer/folder.js` presents groups of 16 for inspection. The CLI uses the same discovery, analysis and durable queue to import an entire result set in sequence.

Inspection streams TAR.GZ content and fingerprints the compressed bytes. Import checks that fingerprint before publishing to `imports/unitypackage-v1/<sha256>` under the data directory. The original Unity tree is kept in `Source/`, with package PNG previews beside it in `Previews/`. Library registration, follow-up scan creation and completion of the import job share one SQLite transaction. A crash after directory publication can leave a reusable completed export on disk. A retry verifies the archive SHA-256 and reuses the output.

`core/packages/unity/folder/` detects a selected Unity project or UPM folder and maps its assets to `Assets/` and `Packages/<name>/`. A Unity project includes its embedded packages and explicit local folder dependencies inside the project. The folder reader fingerprints project metadata, logical paths and the bytes used for import. It passes the original data and GUIDs to the shared Unity report, conversion and publication pipeline. A retry verifies both current source inputs and the stored originals before reusing the result. [Unity embedded dependencies](https://docs.unity.com/en-us/engine/6000.0/manual/packages-list/dependencies-lp/upm-embed), [Unity local dependency paths](https://docs.unity.com/en-us/engine/6000.0/manual/packages-list/dependencies-lp/upm-localpath).

`core/materials/unity/` parses material YAML and TextureImporter metadata and classifies known shader properties. New Unity package imports write `Materials/<guid>/bindings.json`. Each description records the original SHA-256, shader identity, file IDs, UV transforms, scalar and color properties, and the resolved texture path when available. Native Editor texture exports are linked by GUID and file ID. The manifest records the description size and SHA-256, which are checked when reusing the import. Existing completed imports remain readable in their original format.

Channel roles come from the identified shader and its material settings. The current profiles cover Unity Standard metallic, URP Lit and HDRP Lit. Unknown shaders and inherited materials retain property values and texture references. The descriptions record expected color spaces, the texture import flags and when smoothness needs inversion. [Unity Standard](https://docs.unity3d.com/6000.0/Documentation/Manual/StandardShaderMaterialParameterMetallic.html), [Unity URP packing](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/shaders-in-universalrp-channel-packed-texture.html), [Unity HDRP mask maps](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.0/manual/Mask-Map-and-Detail-Map.html).

`core/materials/unity/preview-bindings.mjs` builds an FBX preview plan from those settings. The viewer applies it when a ModelImporter remap or a matched prefab slot points to a unique material with the expected file ID. Image references must resolve to a unique source file within the active library. `public/preview/materials/` binds the color, normal, emission, metallic, roughness and occlusion maps and applies supported alpha cutouts. Packed channels are sampled directly in the Three.js shader. Normal orientation uses the TextureImporter green-channel flag when available. The current preview supports opaque and cutout metallic materials with UV0. Transparent surfaces, specular workflows, height rendering, custom packed layouts and Shader Graph baking are pending. [Unity TextureImporter green-channel flag](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/TextureImporter-flipGreenChannel.html).

`core/engines/` combines Unity, Unreal and Blender discovery adapters. Each reads a bounded set of local directories and installation metadata. Unity matches `ProjectSettings/ProjectVersion.txt` against Hub versions and can identify a candidate from the same series. Unreal matches `EngineAssociation` against known versions or registered build IDs. Discovery reads installation and project metadata without launching the editors. The existing Blender preview calls the Blender discovery adapter when its explicit executable setting is absent.

Schema 8 stores optional export formats on the import job. `core/conversion/` manages model format selection, artifact verification, categorized publication and reuse. Exports are staged under `imports/unitypackage-v1-export-v1/` and keyed by source SHA-256, requested formats, conversion version and the discovered Blender executable identity. Verified originals and generated artifacts are indexed under the same export root. Extraction-only jobs continue to index `Source/` for the existing layouts. The report records the method and SHA-256 for every published artifact and the Blender version when used.

Schema 9 adds the mode and requested Unity version to the job and to the cache recipe. `core/engines/unity/bridge/` owns Unity input filtering, temporary project generation and the Editor process. Its `editor/` directory contains the C# request protocol and export components. `core/conversion/unity-artifacts.mjs` checks the outputs, creates optional Blender previews and publishes them next to direct exports. Prefabs and their individual renderers have separate files under `Models/<guid>/`. Each file records its role, source file ID when available and converter version.

`core/packages/export/` plans and publishes user-directed copies of completed imports. The plan uses the same manifest reader as the paged job report. Selection follows recorded Unity object references, supported relative OBJ, MTL and glTF references, and extracted Unreal package companions. The publisher checks artifact hashes while copying and retains their existing paths. The desktop, browser and CLI use the same plan and publisher. Managed import results and library references remain valid after an export copy.

`core/packages/cleanup/` selects eligible engine source files from the completed import manifest and verifies the original and output hashes. The desktop main process reads the completed job and scan from the existing index and owns the confirmation, saved prompt preferences and system recycle-bin call. `public/package-importer/cleanup.js` monitors the existing import and scan queue for a manually selected cleanup batch.

`core/packages/unreal/` separates source selection, package summary parsing, Pak and IoStore signature checks, inspection and export orchestration. The Unreal CLI operates on this package layer. The native adapter in `core/engines/unreal/bridge/` separates staging, editor selection, project generation, process control and response validation. Its `editor/` contains the trusted Python entry point, dependency resolver, exporters and material reader.

`core/engines/unreal/viewer/` stages allowlisted versioned UE4 packages and runs the configured UE Viewer executable in separate mesh and animation passes. `core/conversion/unreal/viewer/` validates and publishes glTF, BIN and PSA outputs and uses the existing Blender batch adapter for requested derivatives. `core/materials/unreal/` reads material properties and resolves exact package paths. The conversion layer preserves the source parameter dumps and creates a separate textured glTF when a slot and its material parameters have unambiguous matches. The dependency report links meshes, material packages, parent materials and textures. The loose importer records converter identity and adapter revision in the cache recipe. Outputs share the package manifest, export API and index scan. [UE Viewer material export](https://github.com/gildor2/UEViewer/blob/master/Exporters/ExportMaterial.cpp).

`core/conversion/unreal/viewer/actorx/` reads sampled bone tracks and their settings, matches them to a unique LOD0 skeleton by bone names, hierarchy and bind pose, and publishes an animated glTF and animation buffer. The glTF reuses the mesh buffer and available texture links. The manifest links each attached PSA entry to its model and keeps the original PSA and any settings file. Blender uses the animated variant for FBX and GLB when it can preserve the skin and clips. [UE Viewer ActorX exporter](https://github.com/gildor2/UEViewer/blob/master/Exporters/ExportPsk.cpp). [UE Viewer glTF exporter](https://github.com/gildor2/UEViewer/blob/master/Exporters/ExportGLTF.cpp).

`core/engines/unreal/source-mesh/` handles editor-only geometry in stock UE4 package version 522 with EditorObjectVersion 40. It verifies the Engine StaticMesh export and reads the inline or end-of-file MeshDescription payload with the pinned MIT-licensed `@threenative/raw-unreal` decoder. `core/conversion/unreal/source-mesh/` writes one glTF/BIN pair per serialized LOD and records explicit material package dependencies. It uses the shared artifact store, Blender conversion, cleanup and index paths. The shared binder can publish a textured variant using the original material package paths. [ThreeNative Raw Unreal](https://threenative.com/docs/api/raw-unreal/).

`core/engines/unreal/source-mesh/collision.mjs` follows the StaticMesh reference to its owned Engine BodySetup export and reads tagged simple collision data. `core/conversion/unreal/collision/` publishes shapes and settings in the source coordinate system and a self-contained mesh preview in the same meter-scale coordinates as source mesh glTF. The worker reads collision even when UE Viewer has already published the render model. The manifest associates both files with the original mesh and carries them through package exports. [UE4 BodySetup](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/BodySetup?application_version=4.27). [UE4 physics shapes](https://dev.epicgames.com/documentation/en-us/unreal-engine/physics-bodies-reference?application_version=4.27).

`core/engines/unreal/editor-package/` reads the stock UE4 editor package tables and property tags for the source readers. `core/engines/unreal/source-material/` recovers tagged material instance parameters and texture streaming references. `core/materials/unreal/source-parameters.mjs` resolves global overrides through the selected packages and considers only the leaf's exact UV0 texture references for preview. `core/conversion/unreal/source-material/` writes `Materials/<id>/bindings.json` and records parent and texture dependencies. The description retains layered parameters and identifies absent parents and unsupported links. Previews approximate explicitly named maps and still require the original shader to reproduce custom graphs. [Unreal Engine material instances](https://dev.epicgames.com/documentation/unreal-engine/instanced-materials?application_version=4.27).

The source material reader also checks direct tangent-space normal inputs that use a stock 2D sample on UV0. The source texture must declare linear normal-map compression. For RGB or RGBA source PNGs, `normal-map.mjs` accounts for the Unreal green-channel import setting and the glTF normal convention. It writes a distinct PNG when inversion is required and keeps the source PNG. The material description records the parent, resolved texture, original settings and generated path. [Unreal texture properties](https://dev.epicgames.com/documentation/unreal-engine/texture-properties?application_version=4.27). [Unreal glTF export options](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/GLTFExportOptions?application_version=5.3).

`surface-input.mjs` reads UE4 masked blend settings, instance override flags and direct `OpacityMask` texture samples on UV0. `opacity-mask.mjs` retains a validated base-color PNG when its alpha is the mask. For separate grayscale masks it uses linear alpha and combines the verified color at the same dimensions when available. The scoped color trace looks for a unique RGB sample in supported color branches. Where the source color depends on unsupported graph operations, the preview keeps the cutout with neutral color. The glTF binder publishes `MASK`, the material's cutoff and its double-sided setting. [Unreal material blend modes](https://dev.epicgames.com/documentation/unreal-engine/material-blend-modes?application_version=4.27). [glTF material alpha modes](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#alpha-coverage).

`core/packages/unreal/loose/` separates project selection, inventory, queued publication and editor conversion. The direct importer groups packages with their matching sidecars and preserves their relative paths in `Source/Content`. The shared file verifier streams and hashes original files against their recorded identity. The optional editor stage uses a separate workspace and reads from the copied assets. `core/conversion/unreal/` publishes verified editor outputs and can derive GLB previews from FBX through Blender. Its `source-media/` modules validate and publish original UE4 audio and texture data from supported uncompressed and zlib-framed source payloads.

`core/engines/unreal/decoder/` contains the independent decoder process launcher and response validation. Its `worker/Pak/` contains container indexing, path policy and payload extraction for stock Unreal Pak archives. The worker uses a private directory with a fixed request file, a staged input and numbered output files. `core/conversion/unreal/` validates and publishes Editor and Pak outputs through the shared artifact store. `core/packages/unreal/pak/` stages and fingerprints the input, checks the cache and publishes its report and artifacts through the shared import transaction.

`core/packages/unity/bundle/` handles UnityFS source selection and publication. `core/engines/unity/bundle/` manages the AssetsTools.NET worker and validates its responses. Inside the worker, `UnityFs/` validates the bundle, catalogs objects by path ID within each serialized member and resolves bounded resource sections. `Objects/Textures/` reads serialized `Texture2D` fields and `Formats/BlockCompression.cs` decodes the DXT1 and DXT5 blocks. `Objects/Sprites/` resolves the base texture within the same serialized member and crops its pixel rectangle. `Objects/Mesh/` decodes mesh geometry and `Formats/Glb.cs` writes the GLB. `core/conversion/unity/` publishes PNG and GLB outputs and can request an FBX through the existing Blender adapter. Both independent workers use the shared process runner, artifact store and asset index. [Unity sprite rectangles](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Sprite-textureRect.html), [Unity texture formats](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/TextureFormat.html), [Microsoft BC1 and BC3 layouts](https://learn.microsoft.com/en-us/windows/win32/direct3d10/d3d10-graphics-programming-guide-resources-block-compression).

`core/packages/detect.mjs` checks the source header or Pak footer. `core/packages/dispatch.mjs` routes Unity package, UnityFS and Pak imports from the HTTP API, CLI and processing queue. The packages share source selection, job leases, paged manifests and output scanning. Cache keys include the input SHA-256 and decoder recipe. UnityFS records the decoder revision and optional Blender identity. Earlier exports remain available to the index, and a new import uses its decoder revision when choosing a cached result. The Windows builds include the self-contained workers under `resources/unity-bundle/` and `resources/cue4parse/`.

`Objects/Audio/` validates serialized UnityFS AudioClips and reads PCM frames from a single-sound FSB5 bank inside the owner's resource member. `Formats/PcmWave.cs` writes the RIFF header. `core/conversion/unity/bundle-audio.mjs` checks the staged WAV header and publishes it through the shared artifact store. `public/preview/loaders/audio-preview.js` manages local WAV playback in the viewer. [Unity audio import settings](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioImporterSampleSettings.html), [FSB5 format reference implementation](https://github.com/vgmstream/vgmstream/blob/master/src/meta/fsb5.c).

`core/engines/unity/serialized/header.mjs` recognizes standalone Unity file formats 22 and 23 by the declared file size, metadata range, little-endian marker and engine version. The worker's `Serialized/` component opens the standalone file and reads object tables for both standalone files and UnityFS members. `Serialized/Player/` reads the verified Windows Player layouts for Texture2D and AudioClip when trees are absent. `Objects/Resources/` provides bounded slices for both codecs. The UnityFS resolver supplies validated archive ranges. The standalone resolver selects a fixed staged file for a matching sibling reference. Companion discovery is in `core/engines/unity/serialized/companions.mjs`. The package fingerprint records the primary hash and the sibling names and hashes for the queue, manifest and cache. Both inputs use the same durable queue, artifact store and index. [AssetsTools.NET serialized file header](https://github.com/nesrak1/AssetsTools.NET/blob/main/AssetTools.NET/Standard/AssetsFileFormat/AssetsFileHeader.cs). [Unity build content output](https://docs.unity.com/en-us/engine/6000.0/manual/building-and-publishing/build-content-output).

`core/engines/blender/batch.mjs` runs the bundled Python adapter for formats that need conversion. The adapter stages OBJ and glTF dependencies, imports each model once and uses the same scene for the requested derivatives. Legacy previews and package conversions share a serial Blender runner within the server process. The two features have separate scripts and timeout policies.

`core/materials/unreal/packed-layout.mjs` identifies explicit ORM, RMA and MRA parameter roles. An exact texture reference must agree with a matching mask or auxiliary slot in the UE Viewer dump or with serialized UV0 texture streaming data. `core/conversion/unreal/viewer/packed-maps.mjs` publishes a distinct ORM image when the channels need reordering and reuses it across materials. The glTF binder uses the red channel for occlusion, green for roughness and blue for metallic. The import retains the original texture and glTF.

The CLI and stdio MCP interfaces call `AssetIndex` directly. The MCP connector opens the database read-only and applies a library scope to every asset query.

The Electron main process launches the loopback server in a UtilityProcess and injects an ephemeral authorization header in its dedicated browser session. The isolated renderer can choose a folder or resolve the path of a file selected or dropped in the importer. The desktop app prefers port 8178, permits a configured port, and can fall back to an ephemeral port. Indexed user metadata stays independent of the browser port.

`core/packages/folder-processing/` manages the desktop folder run. Schema 14 stores its source, destination, conversion settings, package list and progress. The coordinator uses the existing job queue, waits for indexing and optionally publishes processed results to the common destination. It can resume a paused run or recover a published export in place by checking its saved directory identity and file hashes. `core/packages/export/reuse.mjs` verifies matching processed exports before reusing them on subsequent runs. The run journal stores the reused directory identity and its original export job ID for restart and native cleanup verification. `public/package-importer/folder-processing.js` displays the saved run and requests native cleanup when the server reports it is ready.

Schema 15 adds direct shared storage for new folder runs. `core/packages/storage/` registers one managed workspace per selected destination identity and resolves it for imports, reports, indexing and desktop cleanup. The existing importer stages its result under that workspace and the index points to the published result. The package queue scopes active jobs by workspace. Repeated runs in the same workspace verify cached results and retain their indexed asset IDs. The index binds each library row to the published directory's identity.

`core/packages/discovery/` groups structured folder imports for desktop, CLI and the package search. Unity projects keep their embedded UPM packages within one import. Unreal project and Content boundaries split adjacent loose resources into independent scopes. Archive detection continues alongside Unreal files. The same batch conversion options select the appropriate recipe for each format.

`core/packages/export/processed.mjs` preserves usable source media, derived artifacts and provenance in the destination. The publisher uses the same copy and verification steps as a full export. The native cleanup handler checks the selected destination again before offering to recycle source files.

With compact cleanup enabled, `core/packages/cleanup/retired.mjs` records affected paths and source hashes in an atomic per-import marker before unlinking verified managed native copies. The full import manifest retains provenance. The cache, manifest page and full or individual asset export account for a recorded copy once it is absent. The processed-only export keeps the same manifest format and the managed library is scheduled for a rescan.

`npm run desktop` opens an interactive window. `npm run test:desktop` uses the same bootstrap with a hidden window and automatically creates an isolated data directory when no override is set. Set `ASSET_VIEWER_SMOKE_SCREENSHOT` to save a capture of the demo during the test.

`desktop/window/startup.mjs` waits for the viewer script and the first paint before showing the interactive window. Startup timeouts and renderer exits write `desktop-error.log` in the application log directory and show a native error.
