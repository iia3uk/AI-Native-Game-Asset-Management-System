# Build Asset Viewer

Use Node.js 22.16 or later for source development. The Windows x64 desktop app includes its own Node.js and Electron. Blender is optional and uses the installed executable or an absolute `ASSET_VIEWER_BLENDER` setting.

```sh
npm ci
npm run check
npm test
npm run desktop
npm run build:windows
```

`build:windows` uses the .NET 10 SDK to build the UnityFS and Unreal Pak workers, then writes the NSIS installer, portable executable and `SHA256SUMS.txt` to `release/`. Both workers are self-contained and included in both desktop builds. The build runs with publishing disabled. Running the desktop app from the source tree may download the pinned Electron runtime on first launch. Packaging may download additional Windows build tools.

The Windows build validates that the package includes the thumbnail worker, Three.js loaders, decoder binaries and optional Blender script.

The default installer targets the current user. A desktop shortcut is created, and uninstall preserves application data. The installer and portable app share the same platform-specific data paths. There is no separate portable database beside the executable. Unsigned binaries may trigger Windows SmartScreen. For owner-controlled builds, Electron Builder accepts `CSC_LINK` and `CSC_KEY_PASSWORD`.

Pushing an intentional version tag matching `package.json` runs checks and prepares a draft GitHub Release. The owner reviews the artifact hashes and publishes the draft. Updating installed apps is manual.

## Build the Unreal Pak worker from source

Install the .NET 10 SDK on the build machine and run `npm run build:cue4parse`. The script restores locked dependencies and writes a self-contained executable and its runtime to `release/cue4parse/win-x64/` or `release/cue4parse/linux-x64/`. Run `npm run build:cue4parse -- linux-x64` or specify `win-x64` to select a target explicitly.

Keep the published files together, including `Notices/`. The source CLI discovers the published worker automatically. For a different location, set `ASSET_VIEWER_CUE4PARSE` to its absolute executable path. The Windows desktop app finds its own copy under `resources/cue4parse/` and runs without Unreal Editor or a system .NET installation. A separate Linux worker still uses .NET's platform libraries, including ICU.

The packaged worker includes the CUE4Parse license and upstream notice, the pinned NuGet dependency inventory and the .NET notices. The build checks the inventory against the packaged dependency graph. The Windows package smoke test runs a watched Pak import with the bundled worker and compares the indexed WAV to the source fixture.

```sh
node --test test/packaged-smoke/unreal-pak.mjs
```

## Build the Unity AssetBundle worker from source

Run `npm run build:unity-bundle` with the .NET 10 SDK. As with the Pak worker, you can explicitly select `win-x64` or `linux-x64`. The self-contained output is in `release/unity-bundle/<target>/`. Keep the published files together, including `Notices/`. The source CLI discovers the worker automatically, or you can set `ASSET_VIEWER_UNITY_BUNDLE` to its absolute executable path. The Windows installer and portable app already include the worker and run it without Unity or a separate .NET installation.

## Isolated desktop smoke

On Windows, from PowerShell:

```powershell
npm run test:desktop
```

The command runs Electron with a hidden window, creates a temporary data directory and removes that directory when Electron exits. Set `ASSET_VIEWER_DATA_DIR` to a separate directory if you need to retain the test data. Set `ASSET_VIEWER_SMOKE_SCREENSHOT` to an absolute PNG path to capture the demo. The smoke test checks renderer isolation, the utility server, the local session token, thumbnail generation and cache clearing, a background scan and watched updates with an unsaved metadata form open. It blocks external HTTP requests from the renderer during these checks. Set a distinct data directory when testing an unpacked, portable or installed binary.

Set `ASSET_VIEWER_SMOKE_BUNDLE` to the native UnityFS fixture generated by `test/fixtures/unity-bundle/project.mjs` to check folder watching, inspection, queued import, the artifact report and opening the resulting GLB. Build the worker first when running the test from source.

Set `ASSET_VIEWER_SMOKE_STANDALONE` to the native `BundleProject/Assets/BundleFixture/Triangle.asset` generated by the same fixture to check the standalone import path.

Set `ASSET_VIEWER_SMOKE_WATCH_PLAYER` to the absolute path of the Player fixture's `resources.assets`. The test copies it and its two companions into a connected folder and checks the standalone auto-import switch through indexing.

Set `ASSET_VIEWER_SMOKE_PAK=1` after building the CUE4Parse worker to run the corresponding desktop checks on a stock Pak generated by the smoke test.

Startup and renderer errors are recorded in `%LOCALAPPDATA%\AssetViewer\logs\desktop-error.log` under the default Windows profile. With `ASSET_VIEWER_DATA_DIR` set, the log is under its `cache/logs/` subdirectory.
