# Development status

The current development version is `0.1.0`. The baseline is `aff0312` on `origin/main`. Development is local on `develop/asset-core`.

- Existing capabilities include Fab browsing and review, local folders, manual texture overrides, direct model and texture previews and optional Blender conversion.
- Initial hardening added shared file and metadata guards, origin checks, HTTP regression tests and a bounded Blender queue.
- The opt-in demo has four procedurally generated models, including an animated cabin and a textured OBJ. The fixture generator includes an optional error and duplicate set.
- The SQLite library connects or disconnects chosen roots, performs incremental scans, detects hash duplicates and records missing files and move history. Indexed metadata supports tags, category, review, notes and license. Search supports text, library and file type filters. Results open in the existing viewer.
- Durable background scans show progress and support cancellation and retry. The queue survives restarts and uses SQLite leases to identify interrupted work. Asset updates and a successful job result commit together.
- Folder watching is opt-in per connected root and stored in SQLite schema 3. Native events are grouped into incremental scan jobs. Startup and periodic reconciliation cover missed events and changes made while the app was closed. Hash reuse and the existing path checks apply to both manual and automatic scans.
- SQLite schema 4 stores technical metrics and explicit dependencies for glTF 2.0, GLB, binary VRM and OBJ/MTL. Supported image headers yield texture dimensions. Unchanged sources reuse analysis, including when a dependency is added or removed. Manual and watched scans backfill existing databases.
- SQLite schema 5 adds six editable quality profiles with geometry and texture budgets, size ranges, UV requirements, dependency verification and structure checks. Each result reports the available evidence. Profile overrides live in the local index, survive backups and can be reset individually.
- SQLite schema 6 adds durable model thumbnail jobs. GLB, glTF, binary VRM and polygonal OBJ can produce a 160 × 160 PNG using base geometry. The managed cache has byte and age limits, usage reporting and manual clear. The asset card and CLI can request generation, and read-only MCP can return cached PNG data.
- Schema 7 adds durable `package-import` jobs. The package importer checks TAR.GZ and Unity GUID paths, extracts supported originals without running Unity and saves the manifest, dependency report and conversion report. Completed output automatically gets a scan in the same index. Source files are unchanged. The importer reuses completed output for the same archive SHA-256.
- Core files are organized into `files`, `index`, `analysis`, `processing`, `thumbnails`, `http`, `config` and `packages`. TAR/GZIP handling, Unity package policy, inspection, dependency reporting and publication live in separate modules. The desktop importer interface is in `public/package-importer`.
- The Windows Electron development smoke tested package analysis, background import, indexing and the interactive OBJ preview. A separate isolated test used a native package exported by Unity 6000.3.10f1 with FBX, GLB, PNG, material and prefab. It indexed 11 files. Three.js loaded both extracted models with one triangle each. The retained originals matched the fixture bytes and the report recorded material, texture and prefab links.
- All 57 tests passed on Windows with Node.js 22.16.0 and 24.18.0 and on Ubuntu under WSL2 with Node.js 24.18.0. The syntax check inspected 70 JavaScript files. Regressions cover archive limits and unsafe paths, cancellation and retry, changed source hashes, reused exports, schema migration and a package opening in the existing viewer.
- Browser smoke covered opening the demonstration, playing and pausing its animation, connecting 10 generated fixtures, searching, saving metadata, reopening the model and finding its saved metadata after a page reload.
- The CLI provides search, technical inspection, quality profiles, previews, job inspection, cache maintenance, scan and connection dry runs, watching preferences, duplicate groups, JSON export, diagnostics and backup. The local stdio MCP server exposes ten read-only tools with library allowlists.
- Electron development smoke verified the native bridge, child server, session token and a rendered demo. It generated and displayed the indexed cabin thumbnail, cleared its cache, checked the cabin's 251 and 252 triangle budgets, received an eleventh fixture automatically and preserved an unsaved metadata draft. External renderer requests were blocked.
- The Windows packaging check verifies the Three.js loaders and decoders in the archive and the unpacked Blender script. The unpacked build rendered the procedural cabin and converted synthetic BLEND, USDC and Alembic files through Blender 5.3. The portable build connected and searched a 10-file fixture library, displayed the model and played its animation. A second launch verified that the index was retained and Blender conversion worked in the final portable executable.
- The unsigned Windows x64 NSIS and portable builds are in `release/` with independently verified SHA-256 sums. The current portable build resumed an already queued thumbnail job in an isolated data directory and emitted a 160 × 160 PNG. The previous portable build verified the schema 4 to 5 migration and preserved the technical report, asset ID, review note and history. The NSIS installer has yet to be exercised in a clean Windows profile.
- Synthetic Windows scan times from one run were 109 ms / 22 ms for 100 files, 905 ms / 169 ms for 1,000 and 9,306 ms / 1,975 ms for 10,000. The first scan hashed every fixture and the second reused every hash. These figures describe small text fixtures.
- The checked-in workflows cover CI on Windows and Linux and draft release preparation. GitHub-hosted jobs need a remote run for verification.
- The runtime npm dependency audit reported no known issues. The complete audit reported six moderate entries in the development-only Electron Builder dependency chain. Blender was selected through `ASSET_VIEWER_BLENDER` for the Steam installation on a secondary drive. Live Fab data, complex files, native Linux/macOS desktop builds and a signed installation need separate validation.
- Next package priority is automatic discovery of installed editors and Blender, followed by batch export. Generated FBX and GLB from package sources, Unity binary decoding, Unreal extraction, package folder watching and a persistent Blender preview cache remain open. Textured and compressed thumbnail coverage, collections, rule automation, AI providers and automatic updates remain on the [roadmap](ROADMAP.md).
