# Local security model

The HTTP listener binds to IPv4 loopback, accepts only its active port with `127.0.0.1` or `localhost`, validates supplied browser Origins and requires same-origin JSON for writes. Normal browser navigation can open the app from a link. The app uses CSP, type sniffing protection, resource isolation and a separate sandbox policy for asset SVG.

Library roots are explicit selections. Paths to child files are checked against the canonical root; symlinks and junctions under it are skipped. Fab metadata and Unity text reads are bounded. Source assets remain read-only. The legacy Fab selection document is an intentional metadata write through atomic replacement.

The technical analyzer only reads files discovered under the chosen root and applies byte limits to headers and source text. Metadata lookup joins dependency paths against the same library's index. Absolute paths, traversal outside the library and external URIs are recorded by status. Remote URLs, absolute references and data URI payloads are omitted from the report.

The background thumbnail renderer receives only a verified indexed source and its in-library geometry buffers. It strips texture fetches and other URI-bearing fields before passing glTF geometry to the loader. Byte, geometry and render limits apply in a terminable worker. The HTTP image route derives the cache entry from the asset ID and current source version. The MCP tool checks library scope and returns cached PNG data without exposing local cache paths.

Unity package import reads explicitly selected local files and checks for TAR.GZ with Unity GUID records. It rejects archive links, special records, bad checksums, traversal, device names and path collisions. Staging filenames use validated GUIDs and fixed record names. The importer uses a payload allowlist and excludes scripts, plugins and executables from the published tree. The default extraction mode reads supported YAML as bounded text without starting Unity. Compressed size is limited to 1 GiB, decompressed size to 4 GiB, a member to 512 MiB and a TAR to 30,000 records. Smaller limits apply to metadata and previews. Material descriptions have an aggregate output cap and use fixed filenames under validated GUID directories. The descriptions are JSON data generated from bounded YAML fields and checked against the manifest hashes on reuse. The import checks free space and uses a 10-minute worker timeout. Stages are removed on completion or cancellation. A subsequent import cleans up abandoned stages older than one hour.

Automatic Unity import reads `.unitypackage` files from explicitly enabled library roots. Cache, backup and managed import directories are excluded. The worker rechecks the source against the connected library and validates its SHA-256 during staging. Automatic imports use the engine-free recipe and the same archive and Blender restrictions as manual jobs.

The optional Unity Editor bridge builds a fresh project with bundled C# and pinned packages from the Unity registry. It stages allowlisted assets under `Assets/BridgeInput`, accepts known declarative Unity class IDs and generates new metadata with source GUIDs and available main file IDs. The staging boundary excludes package scripts, custom serialized components, native plugins, settings and embedded UPM projects. Unity runs with the current account's OS permissions. The bridge limits the total staged input to 2 GiB and 4,000 files, checks disk space and limits Unity to three minutes per import.

UnityFS processing runs an independent worker on a staged copy with fixed arguments and a 90-second timeout. It bounds input to 128 MiB, unpacked archive data to 256 MiB and decoder output to 128 MiB, with a 384 MiB managed heap cap. It checks file names, archive offsets and object ranges, rejects unknown container flags and codecs, and does not load dependencies, assemblies or scripts. The worker writes numbered RGBA and GLB outputs. GLB generation bounds vertices and indices and embeds its geometry. Opt-in FBX conversion passes validated GLB to the existing Blender bridge with an overall five-minute budget. The current account's OS permissions still apply to these processes.

Unreal inspection reads bounded package and container headers without running an editor or decoding encrypted data. The optional Unreal CLI export opens known editor-format packages using a fresh project and the installed Python Script Plugin. It copies eligible loose packages and matching companion files while preserving `/Game` paths. It excludes source project configuration, plugins, code, maps and cooked packages. The bridge checks native Asset Registry classes and required dependencies before loading each package. This staging policy reduces exposure. Unreal still parses binary input with the current account's OS permissions, so use editor export with trusted assets. Staging is limited to 2 GiB and 4,000 files, requires free disk space and uses a four-minute editor timeout. Verified artifacts publish from a private stage that is removed after the run.

Independent Pak processing stages a copy and runs CUE4Parse under the current account's OS permissions. The launcher passes fixed arguments without a shell and limits execution to 150 seconds. The process rejects encrypted indexes, checks index and payload checksums, and skips encrypted members and unsupported payload types and codecs. Pak extraction allows up to 2 GiB of input, 128 MiB per extracted file, 1 GiB of total output and 4,000 extracted files, subject to available space. The worker checks archive paths and writes only numbered files. The application rechecks path collisions, output shapes and supported file headers before moving verified files to the managed import directory.

Opt-in package conversion sends OBJ, glTF, GLB and binary FBX to the local Blender executable with a fixed bundled script and disabled auto-execution. The OBJ and glTF adapters rewrite file references to validated package-local inputs. The FBX adapter intercepts the bundled importer's image loading and permits only contained image paths and embedded images. It reports unsupported model formats and does not open package BLEND or USD files automatically. Blender runs with the current account's OS permissions. The bridge bounds copied dependencies, checked artifact sizes, free-space requirements, each invocation and the time spent converting a package.

The desktop user and other processes on the same account are inside the trust boundary. Portable path checks reduce link substitution risk; fully concurrent filesystem changes require stronger native isolation. Browser loaders and Blender native importers are still exposed to malformed inputs. Blender uses an argument vector, factory startup and disabled script auto-execution, with limits on concurrency, input size, timeout and captured output. Its internal dependency resolution runs with the user's OS permissions.
